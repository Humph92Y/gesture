# 에어드럼 (카메라만으로 허공 드럼)

웹캠 하나로 온몸을 찍어서, 주먹을 스틱처럼 쥐고 허공을 내려치면 드럼 소리가 나는 웹 앱입니다. 별도 장비는 필요 없습니다.

- **손**: 주먹을 들었다 내려치기 → 그 위치의 드럼 (하이햇, 스네어, 탐, 플로어탐, 크래시, 라이드)
- **킥**: 오른발을 들었다 내려 놓기
- **하이햇 페달**: 왼발을 바닥에 붙이면 닫힘, 들면 열림 (내릴 때 "챙" 소리)

## 쓰는 법

1. 크롬(또는 엣지)에서 페이지를 엽니다. 카메라는 https 주소에서만 켜집니다 (GitHub Pages 주소는 https).
2. **카메라 켜기** → 머리부터 발끝까지 화면에 나오게 2~3m 떨어져 섭니다. 노트북 내장 캠, USB 웹캠, 휴대폰(휴대폰에서 이 페이지 열기) 모두 됩니다.
3. **캘리브레이션** (약 1분): 기준 자세 → 드럼마다 원하는 자리에서 3번 치기 → 오른발·왼발 높이 맞추기.
4. **테스트 시작**: 화면 안내와 박자 소리에 맞춰 약 80초 동안 칩니다. 끝나면(또는 **종료**를 누르면) 보고서가 브라우저에 자동 저장됩니다.
5. **전체 내보내기**로 보고서 파일을 받아 Claude에게 보내면, 기록을 분석해서 문제를 고칩니다.

## 학습 / 검증 분리

테스트 보고서는 **학습용**과 **검증용**으로 나뉩니다 (기본: 번갈아 자동 지정).

- 학습용 기록으로만 감도 같은 설정값을 고릅니다.
- 그 설정을 한 번도 본 적 없는 검증용 기록으로 정확도를 판단합니다.

보고서에는 매 프레임의 몸 관절 좌표가 들어 있어서, 설정을 바꾼 뒤 같은 동작을 다시 재생해 비교할 수 있습니다 (`tools/evaluate.mjs`).

## 지연을 줄이려고 한 것

- 카메라 프레임이 들어오는 즉시 처리 (`requestVideoFrameCallback`), 가장 가벼운 인식 모델 기본 사용, GPU 사용
- 손이 완전히 멈출 때까지 기다리지 않고, **감속이 시작되는 순간** 소리 재생
- 드럼 소리를 미리 만들어 메모리에 올려 두고, 가장 작은 오디오 버퍼로 즉시 재생
- 화면 오른쪽 "실시간 상태"에 단계별 지연을 표시 (카메라 센서 내부 지연은 브라우저가 알 수 없어 제외)

## 개발자용

```bash
python3 -m http.server 8000          # http://localhost:8000 (localhost 는 https 없이도 카메라 허용)
node tools/evaluate.mjs --synth      # 가짜 동작 데이터로 엔진 자체 점검
node tools/evaluate.mjs --tune       # test-reports/ 의 학습 보고서로 설정 탐색 → 검증 보고서로 확인
```

`index.html?sim=1` 은 사람 대신 가짜 동작 데이터로 화면·소리·보고서 흐름을 점검하는 모드입니다.

| 파일 | 역할 |
| --- | --- |
| `js/engine.js` | 타격 감지 엔진 (손·킥·하이햇). 브라우저와 Node 공용 |
| `js/scoring.js` | 테스트 순서와 채점 |
| `js/audio.js` | 드럼 소리 합성·재생 |
| `js/app.js` | 카메라, 인식 모델(MediaPipe Pose), 화면, 캘리브레이션, 테스트 |
| `js/storage.js` | 보고서 저장 (브라우저 IndexedDB) |
| `tools/evaluate.mjs` | 학습/검증 분리 평가·설정 탐색 |
